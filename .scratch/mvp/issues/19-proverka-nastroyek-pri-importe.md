# 19: Проверка диапазонов при импорте данных

**What to build:** Импорт отвергает файл, настройки которого нарушают пользовательские диапазоны, и не оставляет приложение в состоянии, где настройки больше нельзя сохранить.

**Blocked by:** 09 — Экспорт и импорт данных.

**Status:** done

- [x] Импорт файла с настройками вне диапазонов отклоняется с сообщением, называющим правило.
- [x] Движок отклоняет такой документ до изменения состояния: настройки, журнал и момент наблюдения остаются прежними.
- [x] Экран настроек объясняет уже недопустимые настройки и путь к исходным значениям.
- [x] Тесты ядра и экрана покрывают отказ импорта и отказ движка.

## Comments

- Найдено на ручном прогоне тикета 16: импорт обходил `settingsViolation`, поэтому подсунутый JSON оставлял в движке значение вне диапазона, после чего любое сохранение формы настроек отклонялось — сломать настройки можно было файлом, а починить только кнопкой «По умолчанию».
- Ядро: `DocumentTransfer.selectImport` проверяет `settingsViolation` после разбора и возвращает `ImportRejected(DocumentRejection.invalidSettings, …)` с готовым текстом правила; новый член перечисления — единственное расширение `DocumentRejection`. `WorkDayEngine.applyImportedDocument` проверяет те же правила до `_syncWithClock` и возвращает `WorkDayCommandRejected`, поэтому отказ не трогает ни настройки, ни журнал, ни `lastObservedAt`; тип возврата теперь `WorkDayCommandResult`, `DocumentTransfer.applyImport` его пробрасывает.
- Тексты правил переехали в ядро: `settingsViolationText` в `core/lib/src/settings_validation.dart`. `rejectionText` в оболочке делегирует туда, так что сообщение импорта и подсказка у поля не расходятся.
- Экран настроек: баннер `settings-current-invalid` показывает нарушенное правило для уже сломанного состояния, отказ `applyImport` выводится в `settings-transfer-error`.
- Тесты: `core/test/transfer_test.dart` (+2: отказ импорта с названием правила, отказ движка без изменения документа), `app/test/transfer_test.dart` (+1: файл вне диапазонов отклоняется без диалога и потери данных), `app/test/settings_screen_test.dart` (+1: недопустимые настройки объяснены и исправимы).
- Проверено: `dart analyze` — без замечаний, `dart test` — 197 тестов; `flutter analyze` — без замечаний, `flutter test` — 69 тестов.
- Версия формата не поднималась: схема не изменилась, проверка стала строже только на входе импорта. Собственный документ устройства по-прежнему читается обратно без проверки диапазонов (`PersistedDocument.fromJson`), иначе хранилище стало бы нечитаемым.
- Решение по экспорту: файл собирается из текущего состояния как есть и диапазоны при экспорте не проверяются. Экспорт — это копия журнала и настроек, и запрещать её значило бы отнять единственный способ сохранить историю у того, кто уже поймал дефект прежней сборкой. Такой файл новый выпуск отклонит при импорте, а экран настроек объяснит нарушенное правило и предложит «По умолчанию» — то есть данные не теряются, а недопустимое состояние не переезжает на другое устройство.
