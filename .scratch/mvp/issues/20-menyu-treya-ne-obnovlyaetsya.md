# 20: Меню трея не обновляется при смене фазы рабочего дня

**What to build:** Пункты меню трея должны соответствовать текущей фазе рабочего дня. Меню собирается один раз при старте приложения, поэтому после начала дня из экрана пункт «Завершить рабочий день» остаётся подписанным «(недоступно)», хотя день идёт и завершение работает.

**Blocked by:** 13 — Трей и автозапуск на Windows.

**Status:** done

- [x] После начала дня из экрана меню трея подписано «Завершить рабочий день» без пометки «(недоступно)». — проверено нативно на собранном `work_rest_time_balancer.exe` (release, 2026-11-19): день начат из экрана, правый клик по значку в области уведомлений показывает «Завершить рабочий день».
- [x] После завершения дня (из экрана, из трея или концом рабочего окна) подпись снова говорит, что завершать нечего. — проверено нативно: день завершён из экрана, меню показывает «Завершить рабочий день (недоступно)».
- [x] Меню обновляется там же, где оболочка узнаёт о смене состояния: через тот же обратный вызов, который сохраняет документ ядра. — `_onStateChanged` в `app/lib/main.dart` сохраняет документ и вызывает `TrayMenuRefresher.refresh()`.
- [x] Поведение закреплено тестом: обновление меню после команды на экране, без живого значка в трее. — `app/test/desktop_shell_test.dart`: «смена состояния дня пересобирает меню трея» и «в завершённом дне подпись говорит, что завершать нечего». Тест падает, если вернуть `onStateChanged: _save`.

## Comments

- Найдено на ручном проходе тикета 16 на собранном `work_rest_time_balancer.exe` (release, 2026-11-19):
  - приложение запущено в 23:17 в фазе «не начат», день начат в 23:19 из экрана;
  - правый клик по значку в области уведомлений показывает «Завершить рабочий день (недоступно)», хотя день идёт;
  - обработчик при этом рабочий: `DesktopShell.refresh()` есть, но вызывался только из самого пункта трея, а `WorkRestApp` на смену состояния только сохранял документ.
- Подпись «(недоступно)» — только текст: пункт остаётся кликабельным, поэтому расхождение вводило в заблуждение, а не блокировало действие.
- Исправление: в `DesktopShell` вынесен порт `TrayMenuRefresher` (`refresh()`), оболочка получает его отдельным параметром `trayMenu` и пересобирает меню в том же обратном вызове, что сохраняет документ (главный экран и экран отдыха).
- Проверено: `flutter analyze` — чисто, `flutter test` — 71 тест, `flutter build windows --release` собирается.
