# 01: Каркас приложения и ручной рабочий день

**What to build:** Человек запускает приложение на Windows, Android или iOS, видит, что рабочий день ещё не начат, нажимает «Начать» — и рабочий день идёт. Он может поставить день на паузу, продолжить и завершить его, видит, сколько рабочего времени осталось до конца рабочего окна, а в конце окна рабочий день завершается сам. Вся логика рабочего дня живёт в чистом Dart-ядре, экран только показывает состояние и отправляет команды.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Приложение собирается и запускается на Android, iOS и Windows. — Windows и Android проверены нативно; для iOS нужен macOS с Xcode, здесь не проверялось.
- [x] Ядро — отдельный Dart-пакет без импортов Flutter; экран не вычисляет состояние и время сам.
- [x] Главный экран показывает фазу рабочего дня (не начат, идёт, пауза, завершён) и остаток рабочего окна; доступные кнопки соответствуют фазе.
- [x] Пауза замораживает счёт рабочего времени, возобновление продолжает его без скачка.
- [x] В конце рабочего окна рабочий день завершается сам; после завершения можно начать новый рабочий день в тот же день.
- [x] Команда в неподходящей фазе не меняет состояние и возвращает отказ с причиной.
- [x] Тесты ядра через публичный интерфейс с фейковыми часами покрывают старт, паузу, возобновление, завершение и конец рабочего окна; реальные часы и таймеры в тестах не используются.

## Comments

- Сделано: `core/` — отдельный пакет `work_rest_core` без импортов Flutter; `app/` — Flutter-оболочка с платформами Android, iOS и Windows.
- Ядро: `WorkDayEngine` с командами `startWorkDay`, `pause`, `resume`, `finishWorkDay` и запросом `snapshot(now)`. Снимок отдаёт фазу, доступные команды, отработанное время, остаток рабочего окна и журнал событий, поэтому экран ничего не вычисляет.
- Конец рабочего окна закрывает день внутри ядра при ближайшем обращении к движку: автоматическое завершение пишется в журнал как `workWindowEnded` ровно один раз.
- Экран `app/lib/src/work_day_screen.dart` строит кнопки по `availableCommands` и показывает отказ ядра, если команда пришла не в ту фазу. Оболочка передаёт ядру монотонное время (`MonotonicClock`: настенное время на старте плюс `Stopwatch`), поэтому перевод системных часов не сдвигает ритм.
- Тесты: `core/test/work_day_test.dart` (фейковые часы, без реальных таймеров) и сценарная таблица `core/test/work_day_scenario_test.dart` — паттерн для следующих тикетов; `app/test/work_day_screen_test.dart` проверяет только связку «фаза → доступные кнопки» по ключам, без привязки к текстам.
- Проверено: `dart analyze`, `dart test` (21 тест), `flutter analyze`, `flutter test` (2 теста).
- Проверено нативно: `flutter build windows --debug/--release` (MSVC + Windows 10 SDK), запуск `work_rest_time_balancer.exe` — окно открывается, экран показывает «Рабочий день не начат», «До конца рабочего окна: 23 мин» и кнопку «Начать».
- Проверено нативно: `flutter build apk --debug` и запуск на эмуляторе Pixel 6 (API 36): приложение открывается, «Начать» переводит фазу в «Рабочий день идёт» и показывает кнопки «Пауза» и «Завершить».
- iOS не проверен: сборка требует macOS с Xcode, на этой машине её нет. Платформенная папка `app/ios` создана.
