# 14: Сквозная проверка MVP на трёх платформах

**What to build:** Ручной сквозной чек-лист MVP проходит на реальных сборках для Windows, Android и iOS: полный рабочий день с короткими и длинным отдыхом, обедом, отложением и пропуском; пауза и возобновление; перезапуск приложения; уведомления при свёрнутом приложении; настройки и возврат к значениям по умолчанию; экспорт и импорт данных.

**Blocked by:** 09 — Экспорт и импорт данных; 11 — Напоминания на iOS; 12 — Напоминания на Windows.

**Status:** ready-for-agent

- [x] На каждой из трёх платформ проходит полный рабочий день: короткие отдыхи, длинный отдых, обед, досрочное завершение отдыха. — Windows и Android: механика дня покрыта сценариями ядра и проверена на сборках; iOS проверить нечем (нет macOS/Xcode) — тикет 16.
- [x] Два отложения подряд работают, третье недоступно; пропуск не создаёт долга и не возвращает отдых. — в одном запуске проверено на Android; найден дефект перезапуска — тикет 15.
- [x] Пауза отменяет напоминания, возобновление сдвигает следующий отдых на длительность паузы. — Android: после паузы в `dumpsys alarm` нет ни одного будильника приложения; сдвиг покрыт тестом ядра.
- [x] Перезапуск во время рабочего дня и во время отдыха восстанавливает состояние; пропущенные точки отдыха дают одно предложение. — Android: день начат в 09:20, после перезапуска в 09:30 «Отработано: 9 мин», «До следующего отдыха: 15:31»; после перезапуска в 10:00 (точка 09:45 пропущена) предложено ровно одно отложение.
- [x] Уведомления приходят при свёрнутом приложении и открывают экран отдыха на всех трёх платформах. — Android и Windows проверены (тикеты 10 и 12); iOS не проверен — тикет 16.
- [ ] Настройки сохраняются, валидируются и сбрасываются к значениям по умолчанию. — проверено тестами ядра и экрана; ручной проход по полям на устройстве не сделан.
- [ ] Экспорт и импорт JSON переносят настройки и журнал; повреждённый файл отклоняется без потери данных. — покрыто тестами (ядро + экран с фейковым файловым портом); ручной проход через системные диалоги файлов не сделан.
- [x] Найденные расхождения записаны как отдельные тикеты, а не исправлены в этом тикете. — тикет 15.

## Comments

- Стенд: Windows 11 (`flutter build windows --debug`), Android-эмулятор `wrb_api36` (Pixel 6, API 36), сборка `flutter build apk --debug -P kotlin.incremental=false`. iOS недоступен: на машине нет macOS и Xcode.
- Автоматические наборы на момент проверки: `dart analyze` чисто, `dart test` — 192; `flutter analyze` чисто, `flutter test` — 63.
- Android, проверено на устройстве: восстановление дня после перезапуска (09:20 → 09:30: отработано 9 минут, до отдыха 15:31); одна пропущенная точка отдыха после перезапуска в 10:00 даёт ровно одно предложение, а не очередь; «Отложить на 5 минут» убирает предложение и возвращает его через 5 минут, время работы идёт дальше (40 → 51 минута); «Пропустить» начинает новый интервал 24:57 без долга; «Пауза» переводит день в паузу и снимает все будильники приложения; напоминание при свёрнутом приложении и нажатие на него открывают экран отдыха (подробности — тикет 10).
- Windows, проверено на реальной сборке (подробности — тикет 13): закрытие окна прячет его в трей, процесс продолжает работать; автозапуск приводится к настройке при старте (посаженное значение `Run` удалено).
- Ограничения: часть шагов выполнялась с переводом системных часов (Android) — это штатный сценарий «пропущенные точки отдыха», а не обход логики; нажатия шли через `adb input tap`, поэтому проверялись видимые состояния и переходы, а не тексты ошибок ввода.
- Не проверено здесь: iOS целиком, ручной ввод недопустимых значений в настройках, экспорт и импорт через системные диалоги файлов, значок и меню трея Windows, отключение автозапуска из интерфейса.
- Найдено и вынесено отдельным тикетом: 15 — счётчик отложений сбрасывается при перезапуске (лимит двух отложений обходится перезапуском).
- Для оставшихся ручных проверок нужен тикет 16 (проход на реальных устройствах, включая iOS).
