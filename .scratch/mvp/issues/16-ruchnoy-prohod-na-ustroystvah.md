# 16: Ручной проход MVP на реальных устройствах

**What to build:** Пройти оставшуюся часть сквозного чек-листа на реальных устройствах: ручной ввод недопустимых значений в настройках, экспорт и импорт через системные диалоги файлов, значок и меню трея Windows, отключение автозапуска из интерфейса. iOS выведен из MVP (ADR-0006) и в проход не входит.

**Blocked by:** 15 — Счётчик отложений отдыха сбрасывается при перезапуске приложения; 14 — Сквозная проверка MVP на двух платформах.

**Status:** ready-for-human

- [x] Настройки: недопустимые значения отклоняются с сообщением, прежнее значение сохраняется, «По умолчанию» возвращает исходные значения. — проверено 2026-11-19 на собранном `work_rest_time_balancer.exe` (release): «Обед, длительность» = 0 отклонено сообщением «Длительность обеда должна быть больше нуля», «Короткий отдых, интервал» = 99 — сообщением «Интервал короткого отдыха — от 20 до 30 минут»; документ в `shared_preferences.json` при этом не менялся, после перезапуска настройки остались прежними; «По умолчанию» вернуло 25/180/90/10/13:00/60 и выключило трей.
- [ ] Экспорт создаёт JSON-файл через системный диалог; импорт заменяет настройки и журнал после подтверждения; повреждённый файл отклоняется без потери данных. — системный диалог сохранения открывается и закрывается без потери данных, но ввод пути в нём не автоматизируется в этой среде.
- [x] Windows: значок в трее виден, «Открыть приложение» восстанавливает окно, «Завершить рабочий день» завершает день, при выключенном трее закрытие окна завершает приложение. — проверено 2026-11-18 (тикет 13) и дополнено 2026-11-19: значок виден в «Скрытых значках», левый клик возвращает скрытое окно; правый клик показывает меню «Открыть приложение / Завершить рабочий день / Выход»; при выключенном трее `WM_CLOSE` завершает процесс (проверено — процесса нет), при включённом — прячет окно, процесс жив. Расхождение с подписью пункта «Завершить рабочий день» вынесено тикетом 20 и исправлено.
- [ ] Windows: включение автозапуска из настроек создаёт запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, выключение удаляет её; после перезагрузки системы приложение стартует. — проверено 2026-11-19: включение создаёт значение `WorkRestTimeBalancer` с путём в кавычках, выключение удаляет его, после перезапуска приложения запись восстанавливается по настройке. Сама перезагрузка системы не проверялась.
- [ ] Android: напоминание на заблокированном экране и нажатие на него на реальном устройстве, а не на эмуляторе.

## Comments

- Заведено по итогам тикета 14: перечисленные шаги нельзя выполнить в текущей среде (нет macOS/Xcode, панель уведомлений и системные диалоги файлов недоступны для автоматизации, ввод в поля через `adb input tap` не даёт проверить сообщения валидации).
- 2026-11-18: iOS выведен из MVP (ADR-0006, тикет 18), поэтому оба пункта про iOS сняты — тикет 11 закрыт как `wontfix`, а зависимость от него убрана.
- 2026-11-18, по замечанию с ручного прогона: настройки было не найти — в правом верхнем углу стояла безымянная иконка. Теперь это подписанная кнопка «Настройки», и это закреплено тестом; пункт про ручной ввод значений по-прежнему ждёт человека.
- 2026-11-19: пункт про экспорт и импорт усилен тикетом 19 — импорт файла с настройками вне диапазонов теперь отклоняется до подтверждения, и настройки после плохого импорта больше не блокируются. Ручной проход через системные диалоги файлов по-прежнему за человеком.
- 2026-11-19, ручной проход на собранном `work_rest_time_balancer.exe` (release) с чистым профилем:
  - настройки: недопустимые значения отклоняются с сообщением, документ не меняется, «По умолчанию» возвращает исходные значения — пункт закрыт;
  - трей: значок и меню видны, меню открывается правым кликом, «Открыть приложение» возвращает скрытое окно, ветка «при выключенном трее закрытие завершает приложение» проверена — пункт закрыт;
  - автозапуск: запись `Run` создаётся и удаляется, восстанавливается при старте по настройке; перезагрузка системы не проверялась — пункт оставлен открытым;
  - экспорт: нажатие «Экспорт в файл» открывает системный диалог сохранения, отмена диалога не меняет данные; ввод пути в диалоге не автоматизируется в этой среде — пункт оставлен открытым;
  - найдено расхождение: меню трея не обновлялось после смены фазы дня — заведён тикет 20, исправление проверено на той же сборке.
- Остаток для человека: ввод пути в системных диалогах экспорта и импорта, перезагрузка ПК с включённым автозапуском, напоминание на заблокированном экране реального телефона.
