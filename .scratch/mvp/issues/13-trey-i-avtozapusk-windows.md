# 13: Трей и автозапуск на Windows

**What to build:** На Windows приложение сворачивается в системный трей и продолжает вести ритм и напоминать об отдыхе; из трея можно открыть приложение или завершить рабочий день. Автозапуск включает запуск вместе с системой и запоминается между запусками. Ни трей, ни автозапуск не влияют на правила ритма.

**Blocked by:** 12 — Напоминания на Windows.

**Status:** ready-for-agent

- [x] Приложение сворачивается в трей и остаётся работоспособным: ритм и напоминания продолжают работать. — проверено нативно: после `WM_CLOSE` процесс жив, окно скрыто (`alive=True visible=False`).
- [ ] Из трея можно открыть приложение и завершить рабочий день. — значок и меню создаются при старте, пункты вызывают `activateAppWindow` и `finishWorkDay`; увидеть значок в этой сессии не удалось (панель уведомлений перекрыта окном редактора), ручная проверка — в тикете 14.
- [x] Автозапуск включается и отключается настройкой и сохраняется после перезапуска приложения и системы. — проверено нативно: посаженное значение `Run` удалено приложением при старте (настройка `launchAtStartup=false`); включение покрыто тестом с фейковым портом; запись идёт в `HKCU\...\Run`, поэтому переживает перезапуск системы.
- [x] Поведение при закрытии окна соответствует выбранной настройке трея. — ветка «сворачивать в трей» проверена нативно (окно скрыто, процесс жив); ветка «выйти» — тот же `WM_CLOSE` уходит в стандартную обработку раннера.

## Comments

- Настройки: в `RhythmSettings` добавлены `minimizeToTray` (по умолчанию `true`) и `launchAtStartup` (по умолчанию `false`); они пишутся в документ и переживают перезапуск, старые документы без этих полей читаются со значениями по умолчанию. Ядро хранит только флаг — о трее и реестре оно не знает, правила ритма не изменились.
- Оболочка: `DesktopShell` (`app/lib/src/desktop/desktop_shell.dart`) — трей на `tray_manager` (значок `assets/tray_icon.ico`, меню «Открыть приложение» и «Завершить рабочий день», клик по значку открывает окно) и автозапуск через `win32_registry`: значение `WorkRestTimeBalancer` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, путь в кавычках на случай пробелов.
- Автозапуск приводится к настройке при каждом старте: потерянная запись восстанавливается, выключенная настройка удаляет значение. Если система не дала применить, экран настроек честно сообщает об этом, а настройка не меняется.
- Закрытие окна: `window_manager` 0.6.0 не перехватывает закрытие окна обычного Flutter-раннера (проверено: обработчик не вызывался, процесс завершался), поэтому перехват сделан в раннере — в `win32_window.cpp` добавлен флаг `close_to_tray_`: при `WM_CLOSE` окно прячется вместо уничтожения. Значение приходит из Dart по каналу `work_rest/desktop` (`setCloseToTray`). Так поведение окна соответствует настройке без сторонних оконных плагинов и без deprecated-моста `window_manager`.
- Экран настроек: два переключателя (`settings-minimize-to-tray`, `settings-launch-at-startup`) показываются только на Windows; оба применяются сразу, не дожидаясь «Сохранить», и пишут настройку в ядро, чтобы она пережила перезапуск.
- Проверено: `dart analyze`, `dart test` (192), `flutter analyze`, `flutter test` (63), `flutter build windows --debug`, `flutter build apk --debug -P kotlin.incremental=false`.
- Проверено нативно на собранном exe: посаженное значение автозапуска удалено после старта; после `WM_CLOSE` процесс продолжает работать, окно скрыто.
- Осталось для тикета 14: увидеть значок в трее, открыть приложение и завершить день из меню трея, проверить ветку «выйти» при выключенном трее, включить автозапуск из интерфейса и убедиться в записи реестра.
